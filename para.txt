1. HTTP File Download Validation The OTA process begins by validating the HTTP GET response status and verifying the firmware file size received from the server. A successful HTTP response code (200 OK) and a non-zero file size confirm that the firmware file has been downloaded completely into the modem’s UFS storage without network or server-side issues.
2. UFS File Open Confirmation After downloading, the firmware file is opened from the UFS using AT+QFOPEN, and a valid file handle is obtained. Successful file handle allocation confirms that the file exists in UFS and is accessible for further read operations, ensuring the integrity of the stored firmware.
3. Chunk-Based QFREAD Verification The firmware file is read using AT+QFREAD in fixed-size chunks (256 bytes). Each read operation returns a CONNECT <size> response, confirming that the modem is sending the expected number of bytes. This chunk-based approach ensures controlled memory usage and reliable data transfer for large firmware images.
4. UART Interrupt Data Integrity Check All QFREAD responses are received through UART interrupt mode and stored in a dedicated buffer. Reception is considered complete only after detecting the OK terminator, ensuring that the full response—including header, payload, and footer—is captured without data loss, truncation, or corruption.
5. Exact Firmware Data Extraction From the received QFREAD buffer, only the actual firmware payload is extracted by removing the CONNECT header and OK footer. The extracted data length is validated against the expected chunk size, confirming that the firmware bytes are read accurately and continuously without duplication or missing data.
6. Sequential QFSEEK Offset Validation After each successful chunk read, AT+QFSEEK is used to move the file pointer forward by the exact number of bytes read. The changing data pattern across consecutive reads confirms correct offset movement, ensuring that firmware data is read sequentially from start to end without overlap or restart.
7. End-to-End Firmware Read Completion Check The OTA read process is considered successful only when the total accumulated bytes read match the original firmware file size. This final validation ensures that the entire firmware image has been read correctly from UFS, making the data safe for subsequent flash writing, CRC verification, and application update.
